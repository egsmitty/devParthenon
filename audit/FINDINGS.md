# Dev Parthenon — UX Audit Findings

Generated by `npm run audit:ux` (Playwright drives the real Electron app
through 14 states against a throwaway save; screenshots in `audit/shots/`,
index in `audit/manifest.json`). Reviewed against the §4 rubric: visual
hierarchy, contrast/legibility, state distinctiveness, metaphor clarity,
modal readability, and layout integrity at the 980×680 minimum.

## Verdict

The RPG-temple skin holds together strongly. The completed temple
(`13-temple-complete-wide`) is a real payoff — marble columns with fluting,
gold seals, carved pediment. Mixed states (`11`) are instantly
distinguishable: marble+seal = done, gold runes = in progress, dark stone +
chains = locked. Layout survives the 980×680 minimum with no horizontal
scroll or clipping (`02`, `12`, `14`). Modal hierarchy is clean (`04`), and
the full graded→redemption→pass flow renders correctly end-to-end
(`05`→`09`, including the `Base 83% + redemption 15% = 98%` breakdown).

## Findings (severity-ranked)

### FIXED — this pass
- **[High] Continue button rendered below the fold after answering.** On a
  full lesson chunk, the feedback block + Continue button append beneath the
  options, off-screen; the learner sees no next step without scrolling.
  Fix: `next.scrollIntoView()` + focus the button after an answer resolves
  (`modal.ts` `wireAnswer`). This also sets up keyboard flow (Enter advances).

### Fixed in Phase 6 slice A
- **[Med] Reduced-motion accessibility.** A `prefers-reduced-motion: reduce`
  block now disables every ambient/keyframe animation with usable static
  end-states (steady glow, sparks lit, motes hidden). The audit emulates
  reduced motion and clicks nodes without `force`.
- **[Med] Wrong-answer explanation contrast.** `.why-wrong` lightened to
  #bcc3d3 on the red feedback panel.
- **[Low] Pediment relief legibility.** Relief stroke thickened 1.4 → 2.2 so
  the meander reads at minimum window size.
- **[Low] Glossary scrollbar hint.** Bottom fade mask on the list signals
  more entries below the fold.

### Recommended — remaining
- **[Med] No keyboard navigation.** Options aren't reachable/answerable by
  keyboard (1–4 to pick, Enter to continue, Esc to close), and the modal
  doesn't trap focus. (Phase 6 slice B.)
- **[Low] Locked-node click affordance.** The shake on a locked node is a nice
  touch, but there's no textual "why locked" surfaced on click beyond the
  native tooltip — consider a brief inline toast naming the prerequisite.

## Ideas for the "max it out" pass (beyond fixes)
- Node hover: torch-flicker glow, tooltip cartouche, subtle parallax on the
  light beams.
- Completion moment: a one-time carve/marble-sweep animation + spark burst
  when a stone is set, and a bigger flourish when the pediment unlocks.
- Modal entry already zooms in like a tablet; a matching exit and a page-turn
  or chisel sound-visualizer on option select would deepen the feel.
- Ambient audio-reactive shimmer, animated dust in the light beams, a faint
  moving specular highlight across marble on completed nodes.
